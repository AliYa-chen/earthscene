# Cesium 迁移实现分析

> 2026-10-20：对照当前独立项目的源码进行静态分析。本文区分已编写的实现与迁移计划；没有启动示例服务、进行浏览器画面验收或测量帧率。源码中存在某项能力不等于对应 Cesium 迁移已经完成。

## 项目目标与当前状态

本项目保留完整的首页、文档站、Sandcastle、示例目录及领域功能组织，逐项把适合的能力迁到 CesiumJS。地球、地形、影像、相机、时间和常规地理对象优先使用 Cesium 原生能力；原生没有提供的效果放入可选插件或方法库。必要时允许 Three.js 扩展，但应明确坐标、深度、渲染顺序和资源所有权。

当前有两条入口，不能把两者的完成度混为一谈：

| 范围 | 当前实现 | 尚未完成的工作 |
| --- | --- | --- |
| 完整首页、示例与领域 API | 默认 `src/index.ts` 继续使用既有 Three.js 实现 | 按领域接入 Cesium，并逐个验证示例 |
| Cesium 子模块 | `src/cesium/index.ts` 导出轻量 Viewer、插件契约和体积云 | 不构成现有全部领域 API 的兼容替代 |
| Cesium Viewer | `src/cesium/Viewer.ts` 创建原生 Viewer，保留原生构造选项，以 `.raw` 访问原生能力 | 尚未迁入既有相机、影像、地形等门面 |
| 插件生命周期 | `src/cesium/Plugin.ts` 定义安装结果及销毁契约；适配器支持安装、去重、移除和逆序销毁 | 各插件仍须负责安装失败时的部分资源清理 |
| Cesium 体积云 | `src/cesium/VolumetricClouds.ts` 已编写两阶段后处理与参数控制 | 视觉质量、复杂深度、设备性能与原效果一致性仍需验收 |
| 插件工厂 | `src/cesium/plugins/volumetricClouds.ts` 将云封装为可选插件 | 后续效果按相同边界接入 |

没有新增单独的云 HTML 入口，也没有把完整首页替换为云演示。现有目录名称、历史架构记录或示例数量不能作为 Cesium 全量迁移的证据。面向使用者的项目范围以[项目状态](../../docs/guide/project-status.md)为准。

## 既有 Three.js 效果如何工作

### 参数门面与渲染器分工

大气示例负责地点、相机、时间以及控件绑定。它把参数写入 `scene.atmosphere`、`scene.clouds` 和 `postProcess`；真正的渲染链不在示例页面中。

1. `src/Viewer.ts` 创建 Scene、AtmosphereManager 和 PostProcessingManager。
2. `src/Scene.ts` 与 `src/scene/CloudSettings.ts` 保存用户态，并组成运行时参数交给 manager。
3. `src/rendering/AtmosphereManager.ts` 创建 Takram 的 `AerialPerspectiveEffect` 和 `CloudsEffect`，同步太阳、月亮、纹理和云层。
4. `src/rendering/PostProcessingManager.ts` 准备法线、局部光照掩码与场景深度，把云和大气组合进同一后处理流程。
5. `src/effects.ts` 适配场景缓冲、深度纹理、相机及帧时间；后续再叠加 Bloom、镜头光晕、抗锯齿等阶段。

相关依赖为 `@takram/three-atmosphere`、`@takram/three-clouds`、`@takram/three-geospatial-effects`、`postprocessing` 和 Three.js。它们的 WebGL 实现不能直接作为 Cesium 后处理阶段安装。

### 云密度与光照

既有体积云沿相机射线与地球外侧云层球壳的交段采样，而不是把一张云图片贴到平面上。天气纹理决定大尺度分布，三维 shape 噪声塑造云团，detail 噪声侵蚀边缘，turbulence 纹理扰动形状。高度剖面、覆盖率与各层密度共同决定介质消光和散射。

每个有效采样点估算太阳及天空照明，用 Beer–Lambert 透射率累积散射光；射线变得接近不透明时提前结束。场景深度截断采样距离，避免山体或建筑后方的云覆盖前景。

`src/rendering/AtmosphereManager.ts` 还生成大气查找纹理，并给云和大气共用。云并非独立于空气透视、地表光照及昼夜系统的一层透明图片。

### 云影、光柱与时域重建

既有上游实现包含云颜色缓冲、级联云影和阴影长度缓冲。云影按太阳方向积累光学厚度；大气阶段读取云影与阴影长度，为地表阴影和云缝光照提供共同输入。

上游云阶段还保存历史帧、云前沿深度和重投影速度，执行时域 resolve；启用时域放大时可在较低分辨率采样后重建输出。这些部分是既有画面质量与性能的重要来源，不能用“同样是后处理”推断新实现已有相同效果。

### 参数映射中容易误解的地方

- 既有公开低云参数实际同时改变两个低云层，第二层有高度偏移及厚度倍率；上游另有高云层。新云插件目前只有一组主要云层参数。
- 既有质量档位先应用，再恢复用户显式指定的细节、湍流、霾与云影设置。因此选择低档并不一定关掉所有昂贵特性。
- 既有 `clouds.speed` 表示天气纹理的 UV 偏移速度；新插件 `windSpeed` 表示米/秒，不能直接复制数值。
- 既有场景时钟驱动太阳与月亮，Timeline 可额外将播放态及倍率换算为云速；新插件风速按真实帧时间推进，不会自动跟随 Cesium Clock 的倍率或暂停。
- 既有云随相机高度在约 20–40 km 淡出并卸下阶段。新插件目前在 100 km 以上关闭，未实现相同的渐变与回差策略。
- 既有 `post-process` 与 `light-source` 是不同的地表照明路径。Cesium 场景已经完成自己的照明，不能把整张图像重新当作未照明反照率处理。
- 既有 WebGPU 大气路径没有体积云实现；不能从 WebGL 的能力推定其他渲染后端已支持。

## Cesium 原生能力与扩展边界

下表是实现选择与迁移候选，不是已完成列表。除 Cesium 子模块和云插件外，现有示例仍由默认 Three.js 入口运行。

| 领域 | 优先采用的 Cesium 能力 | 需要保留或单独实现的部分 |
| --- | --- | --- |
| 地球与坐标 | `Globe`、`Ellipsoid`、`Cartesian3`、`Cartographic`、`Transforms` | 既有领域坐标输入与错误边界的转换方法 |
| 相机与交互 | `Camera`、`ScreenSpaceCameraController`、`ScreenSpaceEventHandler` | 既有飞行参数、角度单位、交互优先级和回调契约 |
| 影像 | `ImageryLayerCollection` 及各类 ImageryProvider | 服务配置转换、鉴权、图层排序与样式差异 |
| 地形 | `CesiumTerrainProvider`、`EllipsoidTerrainProvider` | 自定义地形格式的 provider；数据源切换与失败语义 |
| 高度采样 | `sampleTerrainMostDetailed`、场景采样接口 | 地形高度与场景表面高度的区别、取消、批处理和空值语义 |
| 3D Tiles | `Cesium3DTileset` | 既有样式、拾取、高亮、裁剪和采样行为的逐项适配 |
| 常规模型 | `Model` 或 Entity 的模型属性 | 自定义材质、动画差异及模型所有权 |
| 实体与数据 | `EntityCollection`、`DataSourceCollection`、GeoJSON/CZML 等数据源 | 既有数据契约、动态更新和组合图形差异 |
| 图形与文字 | Entity、Primitive、Billboard、Label | 特定文字排版、遮挡规则、贴地分类及透明混合差异 |
| 时间与控件 | `Clock`、`JulianDate`、原生 Animation/Timeline | 自有控件的外观与业务联动；避免两套时钟互相写回 |
| 天空与大气 | `SkyAtmosphere`、`Atmosphere`、`SkyBox`、太阳/月亮及 `Fog` | 与预计算散射不同的视觉表现；自定义云、大气参数的等价性评估 |
| 高亮与后处理 | 轮廓后处理、选中对象机制、`PostProcessStage` | 复杂实例高亮、镜头光晕、定制效果及排序管理 |
| 大规模实例、植被与特殊水面 | 按数据选用原生 Primitive、模型或 3D Tiles | 现有 HISM、草地、水体等能力不能直接宣称有原生等价替代 |
| 体积云 | `PostProcessStage` 提供可扩展合成入口 | 云体采样、消光、散射、云影与重建由插件负责 |

Cesium 的 `CloudCollection` 适合云状物体展示，但不提供本项目所需的完整球壳介质、场景深度截断和全局云影链路。`Fog` 也不是对既有完整大气散射模型的逐参数替代。

## 当前 Cesium 插件机制

`src/cesium/Viewer.ts` 仅增加必要的生命周期管理。原生 Viewer 保存在 `.raw`，默认使用椭球地形且不自动请求 Ion 影像或地形；调用者可以通过原生选项显式提供数据。

`CesiumPlugin.install(nativeViewer)` 返回 `{ value, destroy }`。插件获得的是原生 Cesium Viewer，因此既可通过项目适配器安装，也可由应用直接管理其运行时对象。适配器按 `id` 阻止重复安装，移除时调用插件销毁，在整个 Viewer 销毁前逆序释放插件。

新效果应遵循以下责任划分：

- 插件只拥有自己创建的阶段、纹理、监听器和临时对象，不销毁共享 Viewer、Globe 或外部数据源。
- 安装失败由插件回滚已创建资源；调用方仍应覆盖安装中途异常这一条路径。
- 原生功能可直接使用时保持原生 API，不为每个属性再建立同义包装。
- 插件需要改动场景共享状态时，应记录原值并明确恢复条件，避免卸载一个效果破坏另一个效果。
- 各插件需声明后处理输入、输出色彩空间和排序要求。当前机制只管理生命周期，没有完整的插件依赖图或阶段排序协议。

## 当前体积云实现与边界

### 已编写的处理流程

`VolumetricClouds` 使用 Cesium 的公开后处理类，不创建第二个 WebGL 上下文，也不导入 Three.js。

第一阶段在可配置分辨率下计算云颜色与透明度：按椭球外壳求交，读取不透明场景距离，采样程序化三维噪声，沿太阳方向进行少量额外采样，使用透射率积分。它没有依赖既有云的二进制噪声素材。

第二阶段从阶段名称引用云缓冲，执行四点深度感知放大并合成到原生场景颜色；可选估算可见地面云影、近似雾以及雾中的受云遮挡太阳散射。两个阶段放入 `PostProcessStageComposite`，通过 `inputPreviousStageTexture: false` 保留原生场景作为合成背景。

质量分为 low、medium、high、ultra，分别使用 32、56、88、128 次主采样以及 0.4、0.5、0.75、1.0 倍缓冲分辨率。质量变化重建插件阶段，不重建原生 Viewer。参数每帧归一化；风产生运动时请求下一帧，只有 3D 模式启用效果。

### 球壳与深度

当前使用 WGS84 半轴加高度来近似等高云壳，以公里计算 ECEF 位置。这样避免把云做成平面，也减轻数值量级问题；它不是精确的大地高偏移曲面，也不能消除所有浮点误差。

当前射线只返回最近一段有效云壳；极端空间视角、穿越双段球壳和地平线边界仍需专门验收。采样距离上限为 120 km，因此不是完整全球云层的任意远距离积分。相机位置直接转换为公里并未实现完整的相机相对高低位编码，高频噪声的移动稳定性仍需设备验证。

当前实现按 Cesium 后处理提供的原始深度附件采样 `.r`，通过 `czm_windowToEyeCoordinates` 还原位置并处理对数深度，再与椭球相交距离共同裁剪射线。它与从其他接口获得的 RGBA 打包深度不同；后续不能不辨来源就加入 `czm_unpackDepth` 或再次反解对数深度。Cesium 版本升级时，应核对阶段实际接收的附件与内置函数语义。

普通不透明地形和建筑是主要遮挡目标。透明对象、未写深度内容、地下视角、分类对象及多视锥边界，不在本次静态分析中视为已正确覆盖。缩小云缓冲后，还应检查山脊和建筑边缘是否出现渗漏、光晕或断层。

### HDR 与色彩

云阶段对云辐射独立执行简化曝光映射，合成阶段按近似 gamma 2.2 解码与编码背景。它按原生背景已经过场景输出处理的路径编写，未复制既有预计算大气的物理光度系统。

因此当前曝光、天空亮度、夜间环境、原生 HDR 开关和用户自定义后处理顺序，仍需在锁定 Cesium 版本下分别验证。不得把该近似转换宣称为精确的 sRGB 转换，也不得让原生场景与云重复进行全图 tone mapping。需要保留 HDR 辐射时，应先确定 Cesium 阶段所在位置、附件精度与最终输出责任，再调整云缓冲格式和合成方法。

### 与既有云的差距

- 没有既有多层天气纹理、大气 LUT 与精确太阳/天空辐射共享。
- 没有级联云影图；当前在可见位置按太阳方向即时估算云影。
- 光柱来自少量雾采样，没有独立的阴影长度缓冲。
- 没有历史帧、运动重投影、时域滤波或时域放大；稳定空间抖动不能替代这些能力。
- 缺少与既有时间条等价的云速联动、月相驱动夜间云照明以及质量一致性标定。

这些差距是后续插件演进项。已有类与控件可以作为集成基础，不能据此宣称画面、性能或所有原有开关已等价迁移。

## 按领域实施迁移的顺序

1. **锁定共同基础。** 固定 Cesium 版本与静态资源路径，明确 ESM 入口、样式、Workers 和 Assets 的发布方式；确认独立目录不依赖同级开发仓库。保持完整首页及示例导航。
2. **迁移基础地球场景。** 在现有基础示例内接入原生 Viewer、坐标与相机，统一角度/时间单位、错误与销毁契约。先使示例逐个选择渲染入口，不直接切换全部示例。
3. **迁移影像、地形和采样。** 沿用服务配置，按 provider 能力转换；逐项验证图层排序、透明度、空间参考、地形热切换及不同采样含义。
4. **迁移 3D Tiles、模型和数据源。** 依次核对加载、鉴权、坐标、拾取、样式、动画、动态更新和资源释放，保持示例主题及功能入口。
5. **迁移时间、交互和图形。** 由 Cesium Clock 成为原生场景唯一时钟，控件成为消费者；核对实体、文字、分类、透明与高亮的视觉和事件差异。
6. **接入可选效果。** 在已迁移场景中安装体积云等插件。先验收深度和色彩，再增加多层、云影、光柱及时域重建；特殊植被、水面或 Three.js 扩展单独记录能力边界。
7. **切换默认入口。** 只有共同功能、示例、文档和打包验证形成可评估结果后，才决定切换哪些默认页面。随后再移除不再需要的兼容实现与依赖。

## 验证清单与证据要求

以下是后续执行清单，不表示本次已经通过。每批变更只运行相关检查，并记录具体结果及跳过原因。

| 验证范围 | 要验证的结果 |
| --- | --- |
| 类型与打包 | TypeScript 行为改变运行 `pnpm type-check`；导出或分发改变运行 `pnpm build`；确认 Cesium 子入口没有混入非必需 Three.js 依赖 |
| 项目独立性 | 全新安装、无同级源码依赖、静态资源路径正确、旧发布目标没有恢复 |
| 插件生命周期 | 重复安装、移除、重复销毁、Viewer 先销毁、安装中途失败、质量多次切换后的释放 |
| 基础场景 | 球面/地形视角、飞行、坐标和时间单位；原有首页、示例与 Sandcastle 入口可用 |
| 云空间 | 云下/云中/云上、地平线、高空关闭、南北极、经度跨界及快速移动相机 |
| 深度 | 地形山脊、建筑边缘、近远物体、多视锥、对数深度；透明与无深度内容单独记录 |
| 颜色 | HDR 开关、正午/日落/夜间、原生大气、阴影、曝光和其他后处理组合，避免重复映射 |
| 时间与连续渲染 | Clock 播放/暂停/跳时与真实风速的既定关系；requestRenderMode 下有风/无风状态 |
| 性能 | 不同分辨率、质量档位和设备；分别记录 CPU、GPU、帧率及画面差异，不只比较一个数值 |
| 资源与异常 | 加载失败、无有效深度、WebGL 能力不足、窗口缩放、后台恢复、阶段重建及上下文恢复 |

浏览器验证和性能测试需要单独获得明确执行范围。本次文档分析没有进行这些操作；默认 Three.js 场景的既有测试结果也不能替代 Cesium 场景验证。
